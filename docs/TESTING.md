# Testing

This project keeps the first test layer intentionally small. The goal is to protect the paths that have caused repeated regressions: Hermes artifact discovery, runtime context injection, SSE parsing, artifact focus selection, and Agent Run status selection.

## Backend

Run from the API service directory:

```powershell
cd services\api
.\.venv\Scripts\python.exe -m pytest
```

For day-to-day work, prefer the split runner from the repository root. It avoids
waiting on one opaque full suite and prints the slowest tests in each group:

```powershell
.\scripts\test-api.ps1 -Group unit
.\scripts\test-api.ps1 -Group integration
.\scripts\test-api.ps1 -Group all
```

On Linux/CCI:

```bash
./scripts/test-api.sh unit
./scripts/test-api.sh integration
./scripts/test-api.sh all
```

Current grouping:

- `unit`: adapter parsing, artifact discovery, model runtime config, runtime
  environment, cleanup, skill update, queue classification, and protocol helpers.
- `integration`: ASGI API flows, Agent Run SSE persistence, permissions,
  sharing, cancellation, timeout, and runtime isolation.

Current backend coverage:

- `tests/test_api_integration.py`
  - Agent Run SSE persists run events and creates artifacts from adapter paths.
  - Artifact discovery output can be persisted and served through API permissions.
  - Private, shared, and public session access rules.
  - Shared users can read shared sessions, while non-owners cannot delete.
- `tests/test_artifact_discovery.py`
  - Windows and WSL path normalization.
  - Artifact creation from file paths.
  - Content-hash based dedupe.
- `tests/test_hermes_adapter.py`
  - User prompts are passed to Hermes verbatim.
  - WebAgent does not inject skill mapping or runtime prompt guidance.
- `tests/test_settings_service.py`
  - Listing model configurations never deletes legacy-named user records.
  - Default model repair leaves exactly one default configuration.

Compile check:

```powershell
cd services\api
.\.venv\Scripts\python.exe -m compileall -q app ..\agent-runtime\agent_runtime
```

Full Ruff check:

```powershell
cd services\api
.\.venv\Scripts\python.exe -m ruff check app ..\agent-runtime\agent_runtime tests
```

## Frontend

The frontend uses Node's built-in test runner for the current minimal tests, so no extra test dependency is required.

```powershell
pnpm --filter web test
```

Current frontend coverage:

- `src/services/sse-parser.node.test.ts`
  - Malformed SSE JSON is ignored without breaking the stream.
  - Incomplete trailing SSE events remain buffered until the next chunk or final flush.
- `src/lib/artifact-selection.node.test.ts`
  - `artifact_created` selects new high-priority artifacts.
  - Lower-priority artifacts do not steal focus from the active artifact for the same message.
- `src/components/chat/agent-status-model.node.test.ts`
  - The current session's active run is preferred.
  - `disconnected` is treated as a terminal state.

Production build check:

```powershell
pnpm --filter web build
```

## Dev And Build Directories

The frontend intentionally separates Next.js output:

- Dev server output: `.next`
- Production build output: `.next-build`

Both are ignored by git. Do not manually edit, copy into, or delete these directories while the dev server is running. If the cache needs to be reset, stop the dev server first, then run:

```powershell
pnpm --filter web run clean
```

`apps/web/next-env.d.ts` is generated by Next.js and may switch its route-type reference between `.next/types` and `.next-build/types` depending on the last command run. This is accepted for now as a Next-generated file behavior. Revisit later if typed route generation becomes noisy in commits.

```powershell

.\scripts\test-api.ps1 -Group integration

cd services\api

cd ..\..
```
